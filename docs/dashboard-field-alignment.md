## 已確認與後續 API

- [x] **今日完成率**：分母是今天排程且未取消的任務，分子是其中已完成的任務。現階段使用既有 `GET /api/v1/task` 計算，無須新增 API；若資料量變大或需要跨樓層統計，再考慮後端彙總端點。
- [x] **來源點與目的地**：建立任務的 `source`、`destination` 已儲存於後端，Dashboard 排程與任務路線沿用同一筆資料。任務進度先列機器人目前位置，再列來源點與目的地；沒有定位時明確顯示缺值。Traffic Editor 圖可算出參考途經點。
- [x] **排程範圍**：行事曆顯示今天前後各 30 天。清單由上往下排列；「派工準備中／派工中」與其他任務文字依語言切換。
- [x] **建立後派工**：背景工作每秒檢查新任務並立即提交，不再等到預定開始時間，也不再使用 `AwaitingAssignment`。Development 模擬會直接指定可用機器人，預定時間到達後才轉為 `Running`；外部服務提交後仍須等實際分配結果，期間維持 `Pending` 且 `dispatched=true`。
- [x] **電量歷史暫用模擬資料**：無遙測歷史時，F1 七台註冊機器人顯示固定樣本，圖上明確標示「模擬」。模擬電量不改變後端電量或連線狀態。
- [x] **樓層範圍**：暫時只處理 F1；F2/F3 完成率及電量留空。
- [x] **開發模擬抵達**：Development 的模擬任務由圖上的來源節點沿參考路線走到目的節點。畫面確認模型抵達末端後，呼叫 `POST /api/v1/task/{id}/simulation/arrive`；後端核對 `isSimulated`、`running`、機器人 ID 與任務起終點，再設 `completed` 與 `finishedAt`。方向箭頭抵達時停止循環。此 API 在非 Development 環境回傳 404。
- [ ] **真實派工與執行回報**：強化學習模型尚未接入。現有 HTTP 轉接器會帶 `scheduled_at`，模型需明確保證不會提前執行；另外仍需實際執行路線、定位及完成回報。目前畫面到站只可完成開發模擬。
- [ ] **歷史與網路資料**：後端尚無電量歷史、連線心跳期限或網路健康欄位。機器人連線數仍根據 `hasTelemetry`、`status`；網路面板顯示不可用，未用模擬值冒充在線。

## API 方式

後端是 **C#／.NET 8 的 ASP.NET Core Web API**，由 `Program.cs` 註冊服務、中介軟體和 Controller 路由，回傳 HTTP JSON；不是 FastAPI。任務 API 在 `TaskController.cs`，主要資料與狀態邏輯在 `TaskService.cs`，目前任務資料存在記憶體的 `TaskStore`，尚未接資料庫。Dashboard 使用 `GET /api/v1/task` 與 `GET /api/robots`，每 5 秒重新讀取。開發模擬抵達使用上述受環境限制的 POST；它不取代正式派工與 ROS 2 回報。

## Dashboard 與 Nielsen 十項可用性原則

| 原則 | 本次對照與修改 |
| --- | --- |
| 1. 系統狀態可見 | 任務排程顯示派工狀態或機器人編號；模擬電量標示資料性質；任務完成由後端狀態更新後反映。 |
| 2. 系統與真實世界相符 | 行事曆按時間由上往下；任務顯示建立時的起點、終點與當地時間。 |
| 3. 使用者控制與自由 | 日期可前後切換，「查看全部」進入任務派遣；機器人選單可關閉或切換。 |
| 4. 一致性與標準 | R01～R07 的編號及顏色與即時地圖共用；派工中／已指派與頁面語言一致。 |
| 5. 預防錯誤 | 無路線時仍顯示起終點；真實任務不接受畫面模擬抵達 API；完成率不把取消任務放進分母。 |
| 6. 辨識優於回憶 | 路線面板直接列起點、少量可辨識的途經點及終點；下拉選單直接列七台機器人。 |
| 7. 彈性與效率 | 可以從行事曆切換日期或進入完整任務排程；任務面板可切換機器人。 |
| 8. 精簡設計 | 移除重複的路線技術說明與每筆「參考路線」文字；不列出全部轉彎節點。 |
| 9. 協助辨識、診斷與修復錯誤 | 缺少任務、路線或電量時顯示對應空狀態；模擬抵達的錯誤不會把任務誤標完成。 |
| 10. 說明與文件 | 本報告列出統計口徑、模擬範圍、欄位來源與仍需的正式回報。 |
