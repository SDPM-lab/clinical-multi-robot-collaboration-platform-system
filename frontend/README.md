# 前端

Vue 3 + Vite 醫療機器人協作平台介面。

## 開發與測試

```bash
npm install
npm run dev
npm test
npm run build
```

使用 Node.js `^22.18.0` 或 `>=24.12.0`。`npm test` 執行 Vitest 全部測試，涵蓋登入/API、任務派遣與排程、儀表板、歷史紀錄、機器人狀態、地圖/3D、互動及語系。

登入後前端約每 5 秒檢查後端連線。無法連線或服務回應錯誤時，保留目前頁面並顯示重新連線提示，恢復後自動移除；若後端確認登入已過期，仍需重新登入。恢復後請確認頁面資料已更新。

## 本次介面檢視與修改

### 排程歷史摘要卡片不再隨任務詳情變高

- **現象：**在「排程歷史」點選「任務總數」或「已完成」後，右側有任務資料的詳情卡變高，左側的總數、已完成、已取消、失敗卡片也跟著被撐高。
- **原因：**桌面版左右兩欄的卡片原本共用同一個 CSS Grid 自動列；同一列會依內容較高的右側任務詳情決定高度。
- **修改：**將左側摘要／清單與右側任務詳情／路線拆成各自獨立的兩列版面。摘要卡高度由卡片本身內容決定，不再被右側詳情帶動；右側詳情仍保留完整內容。窄螢幕原有的直向排列不變。
- **效果：**切換總數、已完成等狀態只會篩選清單與更新任務詳情，不會再把摘要卡放大。

### Dashboard 資料提示移到 Daily Schedule 上方

- **現象：**資料更新提示出現在 Dashboard 左上方、樓層篩選附近，與每日排程的內容區分離。
- **修改：**將提示移入右側資訊欄，放在 Daily Schedule 上方，文字靠右對齊並移除白色背景、邊框與陰影；小螢幕也沿用相同的資訊順序。
- **資料意義：**此時間表示機器人快照與任務紀錄 API 最近一次成功回應，不代表 ROS 感測器或機器人遙測一定是最新的。

### 排程歷史清單上移並增加可視高度

- **現象：**中型桌面視窗太早切換成直向堆疊，任務詳情卡排在歷史清單之前，壓縮了清單的可視空間；寬螢幕下也必須避免清單被右側詳情高度推低。
- **修改：**維持左右雙欄的斷點由 1280px 調整為 1100px；摘要卡高度隨字體大小調整，歷史清單緊接在摘要下方並填滿左欄剩餘高度。更窄的畫面採直向排列時，歷史清單改排在任務詳情前。
- **效果：**在可容納雙欄的螢幕上，清單從摘要卡下方開始延伸到頁面底部，可直接看到更多歷史紀錄；窄螢幕仍可向下捲動查看詳情。

### 四張排程統計卡維持原尺寸

- 四張卡的高度配合所選字體大小，不隨右側任務詳情卡的內容高度變化；桌面版兩欄各自排版，右側詳情不再撐大左側卡片。
- 點選總數、完成等卡片仍會篩選清單並更新詳情；選取狀態以背景、邊框和鍵盤焦點樣式辨識，不以放大卡片表達。

### 歷史篩選改用完整機器人名冊

- **現象：**機器人篩選原本只從已載入的歷史任務推算選項；如果資料中只有 M01、M02，就只會看到這兩台，無法選擇目前沒有歷史紀錄的機器人。M01 等代碼也沒有說明機器人類型。
- **修改：**篩選選項改讀取後端 `GET /api/robots` 名冊，而非只讀歷史事件；目前七台依序顯示為 `C01/C02 · 清潔型`、`M01/M02/M03 · 醫療型`、`W01/W02 · 病房型`。各選項仍以後端機器人 ID 作為篩選值，未改動任務紀錄與機器人的關聯；若名冊沒有某台舊紀錄中的機器人，仍會用該紀錄補出可篩選選項。
- **移除重複資訊：**清單上方不再重複顯示筆數，因為上方統計卡已提供任務總數；也移除一般篩選區的「清除篩選」按鈕。若搜尋／篩選結果為空，仍保留「重設條件」作為復原方式，日期範圍不會被重設。
- **測試：**回歸測試確認七台名冊都顯示、機器人類型易辨識、選取 M01 會用後端 ID 找到對應紀錄，並確認清單不再顯示重複筆數。

### 深色主題、可讀性與 ROS 遙測狀態

- **先量測再改色：**瀏覽器讀取原本的設計 token 並按 WCAG 相對亮度公式計算：淺色主題的輔助字 `#929292` 對白底為 `3.11:1`、對 `#EEF0ED` 為 `2.71:1`，低於一般文字 `4.5:1`；深色的 `#939393` 對 `#232624` 為 `4.97:1`。淺色橘色 `#FB9966` 當文字放在白底只有 `2.13:1`。
- **針對已量測的顏色調整：**淺色輔助字保留原色 `#929292`，Robot information 與 Task details 保留原本黃色系面板；深色主題採咖啡棕 `#55423D`、主要文字 `#FFF3EC`、次要色／按鈕 `#FFC0AD`、第三色 `#9656A1`、按鈕文字 `#271C19`，上方選單標題為 `#FFFFFE`；主要文字／咖啡棕、次要色／咖啡棕、按鈕文字／按鈕底色的對比為 `8.64:1`、`6.00:1`、`10.58:1`。這些是指定純色組合，不代表所有半透明／漸層元件均已通過 WCAG 檢測。
- **字級與狀態一致性：**機器人面板欄位標籤、清單輔助資訊、結構按鈕及歷史頁詳情中繼資料提高至至少 11px；深色 Dashboard 與 Robot Status 共用 `#382D29` 頁面底色，Robot information `#55423D`、Task details `#493833`、Today’s completion rate `#654D46` 分層呈現，搭配暖白文字與蜜桃色重點，避免粉色或綠灰色底。使用者頭像首字母固定採白字咖啡棕底。另修正 Dashboard／任務派遣的 inline theme token 覆蓋；窄派遣面板改為單欄，內容可在面板內捲動。
- **機器人遙測新鮮度：**Robot Status 讀取 `/api/robots` 的 `lastUpdate`（後端 ROS 狀態更新時間），顯示最後接收時間及資料狀態；超過 15 秒未更新就標示逾期並提示未連線，未收到遙測或缺少有效時間戳也會明確提示。前端仍每 5 秒輪詢 API；API 回應成功不再等同於 ROS 資料即時。
- **歷史頁版面：**右側任務資料卡恢復依內容自然高度，不再被左側統計列限制；任務資料與路線／時間軸分開排列。原先黃色任務資料面板與路線提示改為咖啡棕與蜜桃色，深色邊線也降低明顯度。

### Dashboard 電量時間軸與字體

- 電量圖將頁面開啟後取得的讀值依本地時間每小時彙整，顯示該時段最新讀值，最多保留五個有回報的時段；橫軸採 24 小時制，滑過柱子可查看各機器人實際讀取時間。紀錄只存在目前頁面，重新整理後會重新累積。
- 中、大字體比例分別為小字的 1.12、1.24 倍；排程歷史摘要卡高度也隨之增加。

## Gestalt 格式塔視覺組織法則

以下依網站實際頁面調整，不把範例當成必須照抄的規定，也不為了形式而替每個頁面增加相同元件。

| 法則 | 在本網站的適用方式 | 檢視與處理 |
| --- | --- | --- |
| **11. Proximity — 接近性** | 任務派遣表單的起點與終點是同一條路線資訊，應相鄰；任務類型、日期與優先級則是不同資訊。 | 起點與終點欄位已在同一表單區域相鄰呈現；維持配對，不與排程時間或優先級混成一組。 |
| **12. Similarity — 相似性** | 相同用途的搜尋、篩選、狀態標籤及操作按鈕應使用一致的尺寸、色彩語意和互動回饋。 | 以共用語意色彩和設計變數為基礎；各頁仍有各自的元件樣式，這次沒有全面統一。不是每頁都需要搜尋框；後續只需盤點功能相同的控制項，避免為一致性增加無用功能。 |
| **13. Common Region — 共同區域** | 同一機器人的關聯狀態應放在清楚的面板中；同一任務的詳情與路線應保持可辨識的分區。 | Robot Status 的電量與溫度目前並列在同一組機器人指標區；Dashboard 與排程歷史也以面板分組。若後續顯示資料時間或來源，應避免讓不同時間／來源的資料看起來像同一筆快照。 |
| **14. Continuity — 連續性** | Live Map 的路徑線、waypoint、起終點及機器人位置應形成容易追蹤的視覺方向。 | 保留路線線條與端點的清楚關係；地圖標籤應避開路線和機器人。這次沒有改動導航路徑繪製，仍需以實際路線和縮放情境檢查標籤遮線。 |
| **15. Closure — 封閉性** | 使用者能從欄位對齊、間距、標題與底色辨識群組，不必替每一列或每個小項都加完整邊框。 | 清單以欄位對齊、留白和分隔線維持分組；不額外為每筆任務增加厚重邊框，以免資訊過度切碎。 |
| **16. Figure–Ground — 圖地關係** | Dashboard 的 3D 建築是背景情境，任務、KPI、樓層控制與資料狀態必須能從場景中辨認。 | KPI 與資訊面板使用獨立底色／玻璃面板區隔 3D 場景；本次把資料更新提示移離樓層控制，並已在瀏覽器確認不再遮住樓層按鈕。正式使用前仍應檢查明暗主題、模型亮暗區及不同螢幕下的文字對比。 |

格式塔法則是組織資訊的設計參考，不代表每個視覺群組都必須加框，也不等同於可用性或安全性認證。

## 其他視覺設計面向

| 面向 | 現況與檢視結果 |
| --- | --- |
| **Visual Hierarchy — 視覺層級** | 以頁面標題、面板標題、主要數值及輔助資訊建立層次；部分 Dashboard 面板同時呈現 3D、趨勢和排程，後續可依操作優先級再精簡。 |
| **Contrast — 對比** | 已計算淺色輔助字、淺色橘色文字及深色輔助字的指定色票對比，並調整未達 4.5:1 的輔助字與文字強調色。玻璃／漸層、狀態色與全站元件仍需逐面板量測；不能據此宣稱整站符合 WCAG。 |
| **Consistency — 一致性** | 共用主題 token、可讀前景色及 focus-visible／disabled／hover 回饋持續使用；這次修正導覽、頁面篩選和 Robot Status 的深色控制狀態。其他頁仍需按操作流程完成控制項盤點。 |
| **State Design — 狀態設計** | Robot Status 明確區分 ROS 資料正常、逾期、未收到及時間戳不明；逾期超過 15 秒時不再顯示為已連線。全站狀態模型和文案仍未完全統一。 |
| **Typography — 字體排版** | 本次機器人面板與歷史詳情的重點中繼標籤調整為至少 11px；其他頁仍有較小字級，需在實際解析度及縮放設定下繼續驗證。 |
| **Color Semantics — 色彩語意** | 完成、錯誤、警告和主要操作有語意色；任務狀態也有文字，不只依賴顏色。狀態色在不同主題下仍應做對比與色覺差異檢查。 |
| **Feedback — 互動回饋** | 多數互動控制提供 hover、focus-visible、selected 或 disabled 回饋；非同步操作有 loading／結果提示，但尚未以共用規格覆蓋所有控制項。 |
| **Aesthetic Minimalism — 極簡設計** | 以資訊面板和留白降低 3D 場景上的辨識負擔；動畫、玻璃效果與多個同時顯示的面板仍應以使用者任務為依據，避免裝飾優先。 |
| **Balance — 視覺平衡** | Dashboard 以左側狀態、中間場景、右側排程形成三區；排程歷史摘要卡和詳情採獨立版面，摘要卡固定原尺寸，不為對齊詳情而拉高。不同視窗大小仍需持續做 responsive 檢視。 |

本次按量測結果調整指定色票並修正已確認的面板問題；對比、全站一致性和操作員工作流程仍需逐元件量測或實測，沒有以未驗證的 CSS 調整冒充已符合。

### 建議優先改善

1. **完成剩餘對比量測：**針對玻璃面板、狀態色、disabled 樣式和不同主題的漸層底色逐頁量測；本次指定 token 的對比改善不代表全站認證。
2. **繼續統一狀態與互動規格：**已修正部分 hover／focus／disabled 和遙測狀態；仍需逐頁確認 loading、success、warning、error 的文案及鍵盤操作。
3. **驗證資料逾期門檻：**目前依 5 秒 API 輪詢採 15 秒 ROS 更新期限；正式部署後需依 ROS 發送頻率、網路延遲和操作員要求確認是否合適。
4. **最後再精簡與平衡資訊：**請操作員依日常任務測試 Dashboard 的 3D、KPI、排程和趨勢資訊層級，決定哪些應預設顯示、哪些可收合。

以上項目跨越多個頁面或需要實際流程／無障礙量測，本次沒有為追求表面一致而做全站大規模視覺改寫。

已改善操作狀態與資料可信度提示：刪除任務期間顯示處理中並防止重複送出；Dashboard 顯示後端資料更新時間或過期提示；任務進度註明位置是估算值、路線是參考資訊。
